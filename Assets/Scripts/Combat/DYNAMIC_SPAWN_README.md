# Система динамического спавна врагов

## Обзор

Система динамического спавна позволяет создавать врагов с условиями спавна и автоматически добавлять на них компоненты. Это идеально подходит для:
- Квестовых врагов, которые спавнятся только при активном квесте
- Случайных встреч, зависящих от прогресса игры
- Врагов с особыми компонентами (например, QuestProgress)

## Основные возможности

### 1. Условный спавн на уровне точки (SpawnPoint)

Каждая точка спавна может иметь свои условия:
- Проверка активности квеста
- Проверка прогресса квеста
- Любая другая логика через UnityEvent

### 2. Условный спавн на уровне зоны (SpawnZone)

Целая зона может быть отключена на основе условий:
- Квесты
- События в игре
- Диалоги

### 3. Динамическое добавление компонентов

На заспавненных врагов автоматически добавляются нужные компоненты:
- QuestProgress для квестовых врагов
- Любые другие компоненты

## Настройка SpawnPoint для динамического спавна

### Шаг 1: Включить динамический спавн

1. Выберите SpawnPoint в иерархии
2. В инспекторе найдите раздел "Динамический спавн"
3. Включите чекбокс "Use Dynamic Spawn"

### Шаг 2: Настроить условия спавна (опционально)

Если вы хотите, чтобы враг спавнился только при определенных условиях:

1. В разделе "Dynamic Spawn Data" найдите "Spawn Condition"
2. Добавьте слушателя события (+ в списке)
3. Перетащите объект с DynamicSpawnHelper в поле Object
4. Выберите нужный метод, например:
   - `CheckQuestActive` - враг спавнится только если квест активен
   - `CheckQuestCondition` - враг спавнится если цель квеста не выполнена
   - `CheckQuestNotStarted` - враг спавнится если квест еще не взят

### Шаг 3: Добавить компоненты на врага

1. В "Components To Add" нажмите "+"
2. В поле "Component Type Name" введите имя класса компонента, например: `QuestProgress`
3. В "On Component Added" настройте компонент:
   - Добавьте слушателя события
   - Перетащите объект с DynamicSpawnHelper
   - Выберите метод `ConnectQuestProgressToHealth` для автоматического подключения к onDie

## Настройка SpawnZone для условного спавна

### Шаг 1: Включить условный спавн зоны

1. Выберите SpawnZone в иерархии
2. Найдите раздел "Условный спавн зоны"
3. Включите "Use Conditional Spawn"

### Шаг 2: Настроить условие для всей зоны

1. В "Zone Spawn Condition" добавьте слушателя
2. Настройте условие аналогично SpawnPoint

Если условие зоны не выполнено, все враги в этой зоне не будут спавниться.

## Примеры использования

### Пример 1: Квестовый враг с QuestProgress

**Задача**: Создать врага, который спавнится только при активном квесте и при смерти прибавляет прогресс квеста.

**Настройка**:

1. **SpawnPoint**:
   - Use Dynamic Spawn: ✓
   - Spawn Condition:
     - Object: DynamicSpawnHelper (создайте GameObject с этим компонентом на сцене)
     - Function: `DynamicSpawnHelper.CheckQuestActive`
     - Parameters: QuestList, Quest
   
   - Components To Add:
     - Component Type Name: `QuestProgress`
     - On Component Added:
       - Object: DynamicSpawnHelper
       - Function: `DynamicSpawnHelper.ConnectQuestProgressToHealth`

### Пример 2: Босс, который спавнится только когда все цели квеста выполнены

**Настройка**:

1. **SpawnPoint**:
   - Use Dynamic Spawn: ✓
   - Spawn Condition:
     - Object: DynamicSpawnHelper
     - Function: `DynamicSpawnHelper.CheckQuestCondition`
     - Parameters: QuestList, Quest, ObjectiveRef, Amount
     - Затем добавьте второй слушатель:
       - Function: `DynamicSpawnHelper.InvertCondition`
       (это инвертирует результат - босс появится когда цель выполнена)

### Пример 3: Зона случайных врагов, доступная после прохождения квеста

**Настройка**:

1. **SpawnZone**:
   - Use Conditional Spawn: ✓
   - Zone Spawn Condition:
     - Object: DynamicSpawnHelper
     - Function: `DynamicSpawnHelper.CheckQuestCondition`
     - Parameters: QuestList, Quest (с пустым objectiveRef для проверки завершения всего квеста)

## Оптимизация и управление памятью

Система автоматически управляет памятью:

1. **Временные враги удаляются**:
   - Мертвые враги удаляются через `corpseRemovalTime` (настройка в EnemySpawner)
   - При удалении трупа он корректно убирается из системы сохранений

2. **Компоненты добавляются только при необходимости**:
   - Компоненты добавляются динамически только на заспавненных врагов
   - Если компонент уже существует, он переиспользуется

3. **Условия проверяются эффективно**:
   - Условия проверяются только один раз при спавне
   - Если условие не выполнено, враг не создается и память не используется

## Интеграция с существующими системами

### Квесты
Система интегрируется с QuestList, Quest и QuestProgress:
```csharp
// Автоматически подключается к Health.onDie
health.onDie.AddListener(questProgress.AddProgress);
```

### Диалоги
Вы можете создать свой метод проверки в отдельном классе:
```csharp
public void CheckDialogueCondition(SpawnConditionResult result, DialogueNode node)
{
    result.canSpawn = // ваша логика
}
```

### События игры
Создайте обработчик событий:
```csharp
public void CheckGameEvent(SpawnConditionResult result, string eventName)
{
    result.canSpawn = GameEventSystem.HasEventOccurred(eventName);
}
```

## Часто задаваемые вопросы

### Q: Можно ли добавлять несколько компонентов на одного врага?
A: Да, просто добавьте несколько элементов в список "Components To Add".

### Q: Как сделать чтобы враг НЕ спавнился при активном квесте?
A: Используйте два слушателя: сначала CheckQuestActive, затем InvertCondition.

### Q: Будут ли враги респавниться с теми же компонентами?
A: Нет, при респавне враги создаются заново и компоненты добавляются снова согласно настройкам точки спавна.

### Q: Можно ли использовать свои условия?
A: Да, создайте свой класс с методом, принимающим SpawnConditionResult, и используйте его в UnityEvent.

### Q: Как убедиться что компоненты настроены правильно?
A: Используйте On Component Added event для настройки полей компонента через рефлексию или публичные методы.

## Технические детали

### Класс SpawnConditionResult
```csharp
public class SpawnConditionResult
{
    public bool canSpawn = true;
}
```
Передается по ссылке в UnityEvent для изменения результата проверки.

### Класс ComponentToAdd
```csharp
public class ComponentToAdd
{
    public string componentTypeName;  // Имя типа компонента
    public UnityEvent<Component> onComponentAdded;  // Вызывается после добавления
}
```

### Поиск типа компонента
Система ищет тип в следующем порядке:
1. Type.GetType(typeName)
2. Type.GetType(typeName + ", Assembly-CSharp")
3. Поиск во всех загруженных сборках

## Производительность

- ✓ Условия проверяются только при инициализации спавна
- ✓ Компоненты добавляются через рефлексию эффективно (один раз при спавне)
- ✓ Нет постоянных проверок в Update()
- ✓ Память освобождается при удалении врагов
- ✓ Совместимо с системой сохранений
