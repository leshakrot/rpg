# Hotfix v2.1 - Исправление отмены рыбалки

## Проблема

В версии 2.0 была проблема с отменой рыбалки:
- Требовалось 2 клика для отмены (первый отменял, второй двигал)
- Кнопки UI блокировали клики по миру
- Во время ожидания поклевки не было визуальной кнопки отмены

## Решение

### 1. Отключение Raycast Target для неважных кнопок

**Изменено в FishingUI.cs:**

Теперь кнопки имеют разные настройки Raycast Target:

- **"Ловить рыбу"** - Raycast Target = `true` (важная кнопка, блокирует клики)
- **"Подсечь"** - Raycast Target = `true` (важная кнопка, блокирует клики)
- **"Отменить"** - Raycast Target = `false` (клики проходят сквозь кнопку)
- **"Тянуть"** - Raycast Target = `false` (клики проходят сквозь кнопку)

**Новый метод:**
```csharp
private void SetButtonRaycastTarget(bool enabled)
{
    if (interactButton == null) return;
    
    // Отключаем/включаем raycast для всех Graphic компонентов в кнопке
    var graphics = interactButton.GetComponentsInChildren<UnityEngine.UI.Graphic>(true);
    foreach (var graphic in graphics)
    {
        graphic.raycastTarget = enabled;
    }
}
```

### 2. Добавлена кнопка "Отменить"

**Новый метод в FishingUI.cs:**
```csharp
public void ShowCancelButton()
{
    // Показывает кнопку "Отменить" с отключенным Raycast Target
    // Позволяет кликать по миру для отмены рыбалки
}
```

**Изменено в FishingSystem.cs:**
- `StartFishing()` теперь вызывает `fishingUI.ShowCancelButton()`
- Кнопка видна во время ожидания поклевки
- Клики по миру проходят сквозь кнопку и отменяют рыбалку

### 3. Улучшена логика InteractWithUI

**Изменено в PlayerController.cs:**
- Упрощена логика проверки UI
- Более понятная структура кода
- Сохранена вся функциональность

## Как это работает

### Сценарий 1: Ожидание поклевки
```
Игрок начинает рыбалку
    ↓
Показывается кнопка "Отменить" (Raycast Target = false)
    ↓
Игрок кликает по миру
    ↓
Клик проходит СКВОЗЬ кнопку
    ↓
InteractWithMovement() обрабатывает клик
    ↓
Mover.StartMoveAction() вызывается
    ↓
ActionScheduler отменяет рыбалку
    ↓
Игрок начинает движение
```

### Сценарий 2: Процесс ловли
```
Игрок ловит рыбу
    ↓
Показывается кнопка "Тянуть" (Raycast Target = false)
    ↓
Игрок кликает по миру
    ↓
Клик проходит СКВОЗЬ кнопку
    ↓
Рыбалка отменяется
    ↓
Игрок начинает движение
```

### Сценарий 3: Поклевка
```
Происходит поклевка
    ↓
Показывается кнопка "Подсечь" (Raycast Target = true)
    ↓
Игрок ДОЛЖЕН нажать кнопку
    ↓
Клики по миру НЕ проходят (это важная кнопка!)
    ↓
Если не нажал - рыба срывается
```

## Важные замечания

### Почему кнопка "Подсечь" блокирует клики?

Это **намеренное решение**! Кнопка "Подсечь" появляется только на 3 секунды, и игрок ДОЛЖЕН её нажать. Если бы клики проходили сквозь неё, игрок мог бы случайно отменить рыбалку вместо подсечки.

### Почему кнопка "Тянуть" не блокирует клики?

Кнопка "Тянуть" видна долго (весь процесс ловли), и игрок может захотеть отменить рыбалку в любой момент. Отключение Raycast Target позволяет кликать по миру для отмены, при этом сама кнопка остается функциональной для удержания.

### Как кнопка работает с отключенным Raycast Target?

EventTrigger (PointerDown/PointerUp) работает даже с отключенным Raycast Target на дочерних элементах, если сам Button компонент активен. Мы отключаем raycast только на визуальных элементах (Image, Text), но не на самом Button.
